# BW Inventory — Android app (Trusted Web Activity)

The Android app is the deployed website wrapped as a [Trusted Web Activity](https://developer.chrome.com/docs/android/trusted-web-activity): a Play Store app that opens the production origin in the user's Chrome, full screen, with no browser toolbar. There is no Android code to maintain. Everything is generated by [Bubblewrap](https://github.com/GoogleChromeLabs/bubblewrap) from `twa-manifest.json`, and the web side (`public/.well-known/manifest.json`, icons, service worker, `/.well-known/assetlinks.json`) lives in the main app.

Only `twa-manifest.json`, `store-assets/` and this file are committed. The Gradle project, keystore and build outputs are generated in CI and ignored by git.

## One-time setup

### 1. Confirm the host

`twa-manifest.json` binds the app to one origin: the `host` field plus every absolute URL in it (`iconUrl`, `maskableIconUrl`, `webManifestUrl`, `fullScopeUrl`, shortcut `url`s and `chosenIconUrl`s). It is set to the custom domain `bwinventory.husainbw.in`; the workers.dev host (`bw-inventory.bw-inventory.workers.dev`) is listed under `additionalTrustedOrigins` so links to it stay inside the app. If the domain ever changes, search-and-replace every occurrence and publish new asset links. The workflow fails early if the host does not serve the manifest and icons.

### 2. Choose the package id

`packageId` (`com.bwinventory.app`) is the app's permanent identity on Google Play. It cannot change after the first upload. Change it now or never.

### 3. Create the upload keystore (locally, once)

```bash
keytool -genkeypair -v -keystore upload.keystore -alias upload \
  -keyalg RSA -keysize 2048 -validity 10000 \
  -dname "CN=BW Inventory, O=BW Inventory, C=IN"
```

`keytool` creates a PKCS12 keystore, which has **one password for both the store and the key** (a separate `-keypass` is silently ignored), so `ANDROID_KEY_PASSWORD` must be the same value as `ANDROID_KEYSTORE_PASSWORD`. Use a password **without double quotes** (Bubblewrap wraps it in quotes when calling the signing tools). Keep `upload.keystore` somewhere safe outside the repo; it is git-ignored. Losing it is recoverable only because Play App Signing (step 5) holds the real app signing key, but you would have to request an upload-key reset from Google.

Print its certificate fingerprint; you need it in step 6:

```bash
keytool -list -v -keystore upload.keystore -alias upload | grep SHA256
```

### 4. Add the GitHub secrets

Repository → Settings → Secrets and variables → Actions:

| Secret                        | Value                                                             |
| ----------------------------- | ----------------------------------------------------------------- |
| `ANDROID_UPLOAD_KEYSTORE_B64` | `base64 -w0 upload.keystore` (macOS: `base64 -i upload.keystore`) |
| `ANDROID_KEYSTORE_PASSWORD`   | keystore password                                                 |
| `ANDROID_KEY_PASSWORD`        | password of the `upload` key                                      |

### 5. Build the first bundle

The web side must be deployed first (push to `main`), because Bubblewrap downloads the live manifest and icons.

Actions → **Android app (TWA)** → Run workflow. It produces `bw-inventory-<version>-<code>.aab` and `.apk` as artifacts. The `.aab` goes to Play; the `.apk` can be sideloaded on a phone for testing (`adb install`). The run summary prints the upload certificate's SHA-256.

`versionCode` is the workflow run number, so it always increases. The version name comes from the `version_name` input, from a tag like `android-v1.2.0`, or from `appVersion` in `twa-manifest.json`.

### 6. Publish the signing fingerprints (Digital Asset Links)

Chrome only hides its toolbar when `https://<host>/.well-known/assetlinks.json` lists the SHA-256 of the certificate the installed APK is signed with. Two certificates matter:

1. **Upload key** (from step 3 or the run summary) — what the sideloaded `.apk` from CI is signed with.
2. **Play App Signing key** — what Play re-signs the bundle with before installing on users' phones. Available only after the first upload: Play Console → Test and release → Setup → App integrity → _App signing key certificate_ → SHA-256.

Add both, then regenerate the file:

```bash
npx -y @bubblewrap/cli@1.25.0 fingerprint add <SHA256> --manifest=android/twa-manifest.json --name upload
npx -y @bubblewrap/cli@1.25.0 fingerprint add <SHA256> --manifest=android/twa-manifest.json --name play
npx -y @bubblewrap/cli@1.25.0 fingerprint generateAssetLinks --manifest=android/twa-manifest.json \
  --output=public/.well-known/assetlinks.json
```

(The first `bubblewrap` invocation asks about JDK/SDK paths; answer "no" to both installs and give any path — the `fingerprint` command does not use them. Or edit both files by hand; the format is in [Google's docs](https://developer.android.com/training/app-links/verify-android-applinks#web-assoc).)

Commit and push to `main`, wait for the deploy, then check `https://<host>/.well-known/assetlinks.json` and Google's [statement list tester](https://developers.google.com/digital-asset-links/tools/generator). Reinstall the app: the toolbar should be gone.

## Play Console checklist

1. Create the app (name _BW Inventory_, app, free), accept Play App Signing.
2. **Internal testing** → create release → upload the `.aab` from the workflow. Add your own Google account as a tester and install from the opt-in link.
3. Copy the app signing certificate SHA-256 (step 6 above) and publish the asset links.
4. Store listing: short and full description, app icon (`store-assets/icon-512.png`), feature graphic (`store-assets/feature-graphic-1024x500.png`), at least two phone screenshots, category _Business_.
5. Policy pages: privacy policy URL `https://<host>/privacy`; Data safety (collects email + name for account, user-entered business data, phone contacts only when the user picks them; encrypted in transit; user can request deletion); content rating questionnaire; target audience 18+; the _Delete my account_ path in Business settings satisfies the account-deletion requirement.
6. **Closed testing** with at least 12 testers for 14 continuous days (required for personal developer accounts created after November 2023), then apply for production access.
7. Every later release: run the workflow (or push an `android-v*` tag), upload the new `.aab`. Web-only changes never need a new app version; the app always loads the live site.

## Testing on a phone before Play

- Sideload the CI `.apk`: `adb install bw-inventory-*.apk`. Until the upload-key fingerprint is live in `assetlinks.json`, Chrome shows a toolbar; that is expected.
- Check: sign-in (email and Google), invite link opens inside the app, password reset (completes in Chrome, session visible in the app afterwards), PDF download and print, WhatsApp share, phone-contacts import, no URL bar once asset links verify.
- Debug asset links on device: `adb shell pm get-app-links com.bwinventory.app` (Android 12+).

## Local build (optional)

Needs JDK 17 and an Android SDK with `build-tools;36.1.0` and `platforms;android-36`.

```bash
npm i -g @bubblewrap/cli@1.25.0
cd android
cp /path/to/upload.keystore .
node ../scripts/android-set-version.mjs --code 1 --name 1.0.0   # or edit twa-manifest.json
bubblewrap update --skipVersionUpgrade --manifest=twa-manifest.json   # regenerates the Gradle project
BUBBLEWRAP_KEYSTORE_PASSWORD=… BUBBLEWRAP_KEY_PASSWORD=… bubblewrap build --manifest=twa-manifest.json
```

Outputs `app-release-bundle.aab` and `app-release-signed.apk` in `android/`. If Bubblewrap's downloads fail behind a proxy, add `--fetchEngine=node-fetch` to the `update` command.

## Changing the app

| Change                                           | Where                                                                                     |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------- |
| Name, colours, start URL, shortcuts, orientation | `twa-manifest.json` (colours also in `public/.well-known/manifest.json`)                       |
| Icon                                             | `public/icons/icon.svg` → `node scripts/gen-icons.mjs` → deploy → rebuild the app         |
| Host / origin                                    | every URL in `twa-manifest.json` + new asset links; the Play listing keeps its package id |
| Push notifications, Play Billing                 | `enableNotifications` / `features` in `twa-manifest.json`; both need web-side work first  |
